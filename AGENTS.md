# Final Frontier — Web Frontend

Next.js rebuild of the legacy `ff-site` React app. Lore archive + authoring UI for a sci-fi TTRPG universe; consumes the `ff-server` Express/Prisma API.

## Environment
- **Node 22 via nvm required** (system node is 18). Run `nvm use` (there's an `.nvmrc`) before any npm/next command.
- Two dev servers: ff-server API on **:3000** (`npm run dev` in `ff-server/`), this app on **:3001** (`npm run dev` here). `NEXT_PUBLIC_API_URL` points at the API (see `.env.example`).
- ff-server's dev script runs `tsx watch` — it auto-restarts on save.
- **Versions come from git tags** (footer + `/api/version`): put `[minor]` or `[major]` in a PR's title/description to cut a release when it merges; otherwise every merge is a patch. See `docs/versioning.md`.
- Production builds use a separate distDir (`.next-build`) so `npm run build` can't corrupt a running dev server.

## Workspace
- `ff-site/` and `vortox-bot/` are **symlinks to legacy repos** — reference only, gitignored, excluded from tsconfig. Never import from any symlink.
- `ff-server/` is also a symlink but is the **live API we actively develop** — it's a separate git repo; commit its changes there (`git -C`), separately from this one.
- Requirements live in `ff-server/FF design document.md` (FR-* / NFR-* ids). The ff-server Prisma schema is the canonical data model; `src/lib/types.ts` mirrors it. Schema changes go through `prisma db push` (no migrations dir).
  - All FR-* requirements are fulfilled. FR-AUTH-4's "display name" was deliberately dropped: usernames are fixed (the archive import maps players by username) and there's no separate display name.
- `archive-to-markdown/` is the episode-import pipeline (Discord export → markdown → API JSON → `/import` page). See its README before touching import/conversion.
  - The `/import` page is open to **any member** (who is always credited as an author; replacing a story's text is for its authors and admins) and renders a **preview** with the real `StoryReader` (`preview` mode: no links, anchors or NPC naming) before upload. Stories go straight to the shelf; there are no drafts. When the form's slug matches a story with a stored `importMeta` (the color → speaker map of its last Google Doc import), `DocxStoryForm` pre-fills those colors and marks the rest "new"; picks made in the form win. A doc's pictures convert to `IMAGE` lines (`meta.images`): the importer lists them with a booru post # field each (checked via `GET /booru/:id`; blank = left out), since story pictures live on booru.vortox.space, never in the DB. The reader shows `StoryLine.imageUrl` through `imageSrc` (the booru proxy).
  - The `/import` page is **story-only**. Admins import *new* episodes on the **`/admin`** page (navbar "Admin", admins only): pick md-to-api.py's JSON files, it previews (conflicts, missing players, NPC voices to create), then dry-runs or imports them all in one transaction (ff-server `POST /admin/episode-import`). The same page runs ff-server's maintenance jobs (story hashes) and shows every run's log. Committing markdown here never changes the live archive: the site reads the production database, so new episodes still have to be imported there. It and `story-md-to-api.py --upload` send each story as one request to ff-server's atomic `POST /stories/import` — nothing partial can be left behind, so there's no eject/rollback UI; a 409 means it's already on the shelf. Episodes (re)import only via the CLI uploaders (`api-import.py`, `episode-json-upload.py`), which use the chunked append endpoints.

## Architecture
- **Production** (NearlyFreeSpeech, FreeBSD; see `ff-server/docs/deploy-nfsn.md`): one origin, where the site proxy sends `/api/` to ff-server and everything else to this app. So the site's own route handlers live under **`/site/`** (`/site/auth/*`, `/site/ff/*`), never `/api/`. `next.config.ts` builds a standalone server (`output: 'standalone'`) with `images.unoptimized` (sharp has no FreeBSD build). `src/lib/api.ts`: server code reads `API_URL` at runtime (loopback to ff-server in prod), browser code `NEXT_PUBLIC_API_URL` (built as `/api`). Merging to `main` deploys via GitHub Actions, which runs `scripts/deploy-nfsn.sh` (builds HEAD in a temp worktree and restarts the `ffsite` daemon); see the runbook's "Deploying".
- **Auth**: the ff-server JWT lives in an httpOnly cookie `ff_token`, set by the `/site/auth/*` route handlers. Server components call `getSessionUser()` / `getToken()` (`src/lib/auth.ts`); client components read `useSession()` and send authenticated API calls through the generic proxy `/site/ff/[...path]`. Browser JS never sees the token.
  - Password changes go through `/site/auth/password` (not the proxy): ff-server revokes every older token and returns a fresh one, which that route swaps into the cookie.
  - `SessionUser.mustChangePassword` (seeded/reset accounts): `PasswordChangeGate` (in the root layout) pins the user to `/account` until they change it; ff-server refuses their writes meanwhile.
  - Admins see a "Reset password" control on a player's `/users/[username]` page (`ResetPasswordControl` → ff-server `POST /users/:id/password-reset`): back to the default password, forced change, every session signed out. Not shown on admin profiles.
  - Character and persona avatars can be uploaded (`AvatarField`, `AvatarUploadButton`, `src/lib/avatarUpload.ts`): PNG, at most 14x14 and 16 KB. The picked file goes up as a `data:` URL in the record's normal `image` field, and ff-server stores it and writes back `/api/avatars/<sha256>.png`, which `imageSrc` routes through `/site/ff`.
  - `/account` edits the user's own profile (bio, wiki username, booru avatar by post ID) and password; `/users/[username]` is the public profile. Link people with `UserLink`.
- **Reconstructed episodes**: `Episode.reconstructed` marks episodes rewritten from memory, not recovered from logs (FF1's lost early episodes, manuscripts in `archive-to-markdown/md/ff1/reconstructed/`, `"reconstructed": true` in `meta/ff1.json`). They're stored before the archive (FF1 episode_no -3..0) with no message timestamps (undated `**Account**` headers in the markdown), show as "R1"…"Rn" via `episodeNumberLabel` (`src/lib/seasons.ts`) with a "reconstructed" tag, and never count as a character's first appearance when an archived episode exists.
- **In-universe dates are GUY calendar integers** (equinoxes since the GUY epoch; 1 equinox = exactly 1 Earth day), e.g. `Character.dob`. Use `src/lib/guy-time.ts` — an identical copy lives at `ff-server/src/utils/guy-time.ts`; keep them in sync. Real-world timestamps (messages, playedDate) stay DateTime.
- **User rich text** (character blurbs, item descriptions, bios, commentary) is stored as ff-server-sanitized HTML with plain text entity-encoded: render it with `RichText`, never as a text node (that shows `&amp;`). Editors decode it for the textarea (`richTextField` in the editor schemas, `decodeEntities` in `src/lib/html.ts`).
- **Record editing is schema-driven**: field definitions live in `src/lib/editor/schemas.ts` (`EDITOR_SCHEMAS`); `RecordEditor` renders/validates/submits any registered kind. Add fields there, not in per-page forms.
- **Category search** (FR-SR-1) uses the shared `IndexScan` component; season/episode slugs and deep links come from `src/lib/seasons.ts`.
- **Story categories**: a story's branch comes from its campaign's `Season.kind` (`storyBranch` in `src/lib/stories.ts`: MAINLINE/PLANNED = mainline, SIDE or no campaign = spin-off) and `Story.canon` (default true; `canon: no` in manuscript frontmatter, the import form's non-canon box, or an admin's "shelf settings" on the story page). Vortox Machina is the story-only SIDE season `VM` (ff-server `npm run seed:story-shelf`, which also marks the known non-canon stories), hidden from the Archives roster like T&L. `/stories` filters by season (one chip per season on the shelf) and canon status, and tags each card with its season code and canon status; story stats are word counts (`wordCount`, from ff-server), not line counts.
- **Player characters (campaign cast)**: ff-server `GET /seasons/:season/cast` finds a campaign's player characters from its transcripts: in each episode, every player's most active character (QUOTE + ACTION messages). A player's main leads nearly every episode they attend; a side character (Bail, Ibraxas) only the episodes it carried. Nobody is excluded, so in FF4 (the only campaign with a GM) the GM's busiest NPC per episode counts too; admins curate those (demote to NPC). Admins can also add characters per campaign by hand (`Character.mainIn`, `SpeakerAdmin` → "add to cast…" → `PUT /characters/:id/main-in`): the only way a story-only campaign gets a cast. `/archives/[season]` lists the cast as avatars (`CastAvatar`, name on hover), most messages first; each episode page lists the ones that led it.
- **Character colors**: `Character.color` is the dark-mode color, `Character.colorLight` an optional light-mode override. Always resolve display colors with `characterColor(name, color, mode, colorLight)` (`src/lib/characterColors.ts`): each theme takes its own color, then the legacy table, then the other theme's color made readable (`suggestColorFor` in `src/lib/colorContrast.ts`: same hue, lightness moved in OKLCH until 4.5:1 on that theme's backgrounds), then the name hash. The character editor's two color fields (`theme` in the schema) show that resolved color as "auto" when empty, so the suggestion and the site always agree. Look colors up by the character's own name, never a persona's display name.
- **Character index**: `GET /characters` returns `quoteCount` and per-campaign first `appearances`; `CharacterIndex` sorts by them (`src/lib/characterSort.ts`; default: times quoted, most first, since there's no "main character" field) and can group by campaign, where a character is listed under every campaign they appear in.
- EMBED message `text` is a JSON string `{title?, description[], footer?}`; the transcript reader regroups consecutive messages by player+character into Discord-style blocks.
- **Story dialogue presentation**: `Story.format` (`SCRIPT` | `PROSE`) switches script-style vs novel-style rendering. A NARRATION `StoryLine` may carry a `segments` JSON annotation (`[{text, characterId?, speaker?, italic?, bold?}]`) — the universal inline-run primitive for embedded dialogue *and* inline italic/bold — with segment texts concatenating verbatim to `text` (server-derived, so they never desync; search/scan stay on `text`). Block section headings use the `HEADING` line type. Import: `[spoken]{Speaker}` dialogue spans, `*italic*`/`**bold**` emphasis, and `## Title` headings in the story markdown; the docx converter maps Heading 1→chapter, Heading 2→heading line in prose.
- **NPC voices**: a doc color that stands for "whichever NPC is talking" (gray `#666666` defaults to it in the import form) imports as *unnamed NPC voices*: `[spoken]{?}` / `> ?:` in a manuscript, a segment `{npc: true}` / a DIALOGUE line `npcVoice: true` with no speaker. The importer's optional modal (`NpcVoiceNamer`) names them per quote; otherwise the story's authors or an admin click one in `StoryReader` (`VoiceNamePopover` → `PATCH /api/stories/:slug/voices`). NPC quotes never link a character: viewers get the name as a tooltip with the `help` cursor; editors get a `pointer`, and unnamed ones a dotted underline. A re-import (`PUT .../import`) keeps names for quotes whose text is unchanged.

## Conventions
- **No MUI, no Tailwind, no component frameworks.** Hand-rolled SCSS Modules + design tokens (`src/styles/_tokens.scss`). Art direction: retro sci-fi × indie-web Neocities.
- Theming: `data-theme` attr on `<html>`, persisted in localStorage key `colorMode` (legacy-compatible). All colors via CSS custom properties — never hard-code.
- API calls go through `src/lib/api.ts` (handles the `{status, data|message}` envelope; `apiPaged` for endpoints that return `total/page/limit`).
- 4-space indent, single quotes (matches legacy codebase style).
- API-backed index pages need `export const dynamic = 'force-dynamic'` or they prerender against a dead API at build time.

## Data & testing
- **The DB is disposable dev data, not canonical — the archives are.** Canonical source for transcripts: `archive-to-markdown/md/` hand-edited markdown, imported via `md-to-api.py` (FF2/FF3; FF4 as episodes get edited — `discord-exports/` JSON is FF4's reference/raw material, converted to markdown by `ff4-to-md.py`; unedited FF4 episodes can still import directly via `discord-json-to-api.py`). See `archive-to-markdown/notes/HANDOFF-ff4-editorial.md`. Postgres `episodes`/`messages` rows are just an import target — freely delete-and-reimport an episode to fix drift between the DB and a pipeline change, no need to preserve DB state for its own sake. Still check for real user-authored data first (commentaries, persona/alias assignments) before wiping — `episode.service.ts`'s `deleteEpisode` cascades those away too.
- The local Postgres is seeded with the real archive: seasons FF2 (22 episodes) and Vortox Machina, ~24k messages. **Never re-run `npm run seed` casually — it wipes user-authored content.**
- Dev logins: username = player name, password = `<lowercase>123` (e.g. `Trey` / `trey123`, role ADMIN) — see `ff-server/prisma/seed-legacy.ts`. Seeded accounts must change their password on first login; to skip that in dev, `UPDATE "User" SET "mustChangePassword" = false;`. The Archivist can't log in.
- Verify UI changes end-to-end with headless Playwright driven from the session scratchpad (`npm i playwright` there; chromium is already cached). `.pixel-label` text renders uppercase — compare `innerText` case-insensitively.
